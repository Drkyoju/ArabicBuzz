## كيف تعمل الذاكرة؟

1. كل رسالة واردة/رد (عند التنفيذ الظاهر) تُمرَّر عبر `mirrorChannelTurnToRoom` → جدول `room_posts` بقناة `telegram` و`external_id` = معرّف الشات.
2. قبل كل دورة وكيل: `buildTelegramChatMemoryAr` يجلب:
   - آخر ~٤٨–٦٤ سطراً **لهذه المحادثة فقط**
   - حقائق ثابتة مستخرجة + ذاكرة الغرفة
   - **ملخص أسبوعي أخير** إن وُجد (`[ملخص أسبوعي تيليجرام]` في `room_memories`) — للوكيل فقط، بلا إعادة إرسال
   - مهام ملفات معلّقة (`telegram_file_jobs`)
   - مرفقات مرآة (`telegram_attachments`) + ذاكرة حيّة (`recent-media`)
3. تُحقن كتلة الذاكرة في system prompt — الوكيل ملزم بقراءتها قبل أي سؤال توضيحي.
4. خميس الرياض (١١–١٦): ملخص أسبوعي للمجموعة **معطّل افتراضياً** (`TELEGRAM_GROUP_PUSH` + `TELEGRAM_WEEKLY_GROUP_DIGEST`)؛ عند التفعيل: مرة واحدة بالأسبوع مع قفل (`lib/digest/weekly-group-chat.ts`) — منفصل عن ملخص المدير.
5. بعد إعادة تشغيل السيرفر: المرآة في Postgres تبقى؛ الذاكرة الحيّة تُستعاد من المرآة عند الحاجة (`hydrateRecentMediaFromPersist`).

## ماذا تجرّب على تيليجرام (بعد النشر على CranL)

1. `/ping` ثم `/status` — تأكد أن الربط وhops سليمة.
2. **ذاكرة:** أرسل «اسمي للتجربة: …» ثم لاحقاً «وش اسمي؟» — يجب أن يتذكر من سجل الشات.
3. **بحث ويب:** `ابحث في جوجل عن رؤية 2030` — ملخص مختصر + روابط (بدون طلب مفتاح).
4. **خريطة:** `أين تقع برج المملكة` — إحداثيات + رابط OSM/خرائط جوجل.
5. **مرفق TG:** أرسل PDF ثم `عدّل …` أو `انسخ صفحة فاضية بعد …` — يعمل على الملف المرسل (ليس فقط Drive).
6. **صوت → ملف جديد:** ملاحظة صوتية «أنشئ ملف مذكرة بعنوان … والمحتوى …» — يستلم ملفاً جديداً كمرفق.
7. **اختصار:** `إحاطة الصباح` أو `كم موعد عندنا؟` — رد موجز بلا محاضرة.

فحص استضافة: `GET https://arabicbuzz-fooc9h.cranl.net/api/health/free` و`GET …/api/webhooks/telegram`.

## لا سبام للمجموعة — إرسال تلقائي معطّل افتراضياً (آب ٢٠٢٦)

**ما كان يرسل بلا طلب في «عمل الجمعية» (كرون / مجدوَل):**

| المصدر | الملف | السلوك السابق |
| --- | --- | --- |
| ملخص صباحي | `lib/digest/morning-room.ts` | يُرسل للمجموعة في نافذة الصباح |
| ملخص أسبوعي للمجموعة | `lib/digest/weekly-group-chat.ts` | خميس الرياض |
| تذكير مواعيد (~ساعة) | `lib/rooms/appointment-reminders.ts` | يتكرر مع كل نافذة موعد |
| تذكير مواعيد نظامية | `lib/rooms/deadline-reminders.ts` | 30/14/7/1 يوم |
| تذكير مهام متأخرة | `lib/digest/overdue-nudge.ts` | مع نافذة الصباح |
| ملخص المدير تيليجرام | `lib/digest/director-weekly.ts` | خميس (بريد منفصل) |
| نشرة heartbeat / مهام مجدولة | `app/api/crons/runner` | قناة telegram |
| إشعار بريد IMAP / طاقة بريد | `imap-sync` / `mail-energy-runner` | يصل لنفس الشات المربوط |

**القرار:** الصمت أفضل من السبام. كل ما سبق **معطّل افتراضياً** ولا يُرسل للمجموعة إلا بعد تفعيل صريح:

0. **صمت مطلق (افتراضي):** `TELEGRAM_SILENCE_UNSOLICITED` = مفعّل عند عدم التعيين — يمنع أي `sendMessage`/`sendDocument` للمجموعة خارج سياق رد على تحديث وارد (ويب هوك). عطّله بـ `=0` فقط إن أردت الملخصات لاحقاً.
1. المفتاح الرئيسي: `TELEGRAM_GROUP_PUSH=1`
2. ومفتاح الميزة المطلوبة، مثلاً `TELEGRAM_MORNING_DIGEST=1`

بدون إيقاف الصمت + المفتاحين معاً → لا إرسال كرون. القفل اليومي/الأسبوعي (`claimDigestDayKey`) يبقى موجوداً عند التفعيل لاحقاً.

فحص الحي: `GET /api/health/free` → حقل `telegramGroupPush` (`silenceUnsolicited: true`، وكل `features` = `false`).

**مسار كان يفلت من البوابة السابقة:** كرون GitHub يستدعي `runReadyTelegramFileJobs` + `resolveAndRunPendingPdfJob` فيرسل `sendDocument` للمجموعة بلا `TELEGRAM_GROUP_PUSH`. أُغلق: صمت في `emit*` + تخطي كرون + إيقاف جدول GitHub Actions.

**حماية فورية:** سير عمل GitHub `Cron runner` **معطّل بالجدول**؛ `workflow_dispatch` يرفض POST طالما `silenceUnsolicited` ليس `false`.

**ما بقي مسموحاً:** رد البوت **فقط** عندما يكتب مستخدم طلباً (رد واحد لكل رسالة — لا نسخة ثانية عند فشل `editMessageText`).

## لماذا كانت الرسائل تتكرر؟ وكيف مُنعت (آب ٢٠٢٦)

**أسباب التكرار (التي ظهرت في مجموعة «عمل الجمعية»):**

1. **إعادة تسليم الويب هوك** — تيليجرام يعيد `update_id` إذا تأخر الرد؛ بدون قفل يظهر ردّان لنفس الطلب.
2. **سبام حالة التشغيل** — رسالة طويلة «استلمت / المقعد / القصد / الأدوات» ثم الرد النهائي (يبدو كإرسال متكرر).
3. **الأدوات + الرد النهائي** — `send_message` / `send_file` / إحاطة مع `sendTelegram` ترسل للمجموعة أثناء الدورة، ثم البوت ينشر الرد مرة أخرى.
4. **تذكير المواعيد/المواعيد النظامية** — سباق بين مثيلات الـ cron: إرسال ثم تعليم «أُرسل» يسمح بإرسال مزدوج.
5. **ملخص الصباح** — سابقاً تعدد نطاقات → نفس `chat_id`؛ اليوم قفل يومي + هدف واحد لكل شات.

**الوقاية الحالية:**

| طبقة | السلوك |
| --- | --- |
| `claimTelegramUpdate(update_id)` | تجاهل تسليم مكرر لنفس التحديث (Redis NX أو Prisma أو ذاكرة) |
| `claimTelegramMessageKey(chat, message_id)` | حماية إضافية لنفس الرسالة |
| `claimTelegramChatTurn` | قفل أثناء التنفيذ + نافذة «أُجيب مؤخراً» لنفس البصمة |
| مجموعات | **بدون «جاري…»** — رسالة نتيجة واحدة فقط. إن وُجد ack (خاص): تعديل فقط — **ممنوع** `reply` ثاني عند فشل التعديل |
| أدوات تيليجرام | لا إرسال ذاتي لنفس الشات عبر `send_message`/`send_file` أثناء الدورة |
| ملخص صباحي / تذكير موعد / موعد نظامي / ملخص أسبوعي للمجموعة | **معطّل افتراضياً** (`lib/telegram/group-push-policy.ts`)؛ عند التفعيل: `claimDigestDayKey` **قبل** الإرسال |

لا تطلب من المستخدم «أعد الإرسال» لمهمة قيد التنفيذ — نفّذ مرة واحدة وانتظر طلباً جديداً.

## حدود صادقة

- Drive يحتاج ربط Google من الموقع مرة واحدة.
- مشاركة ACL على Drive غير متاحة من البوت — رابط العرض فقط.
- خاص فقط لمن ضغط Start؛ وإلا منشور في المجموعة.
- بحث «جوجل» = مسار مجاني DDG/ويكيبيديا/gov.sa (ليس Firecrawl/Brave إلا بمفتاح اختياري موجود مسبقاً).
- هيرميس واتساب ≠ هذا البوت.
